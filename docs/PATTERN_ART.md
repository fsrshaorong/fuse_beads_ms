# 图案分辨率与美术制作

豆子统一为 2.6 mm 档 Mini，单板 52×52 钉位。图案的格数决定可表达的细节和实际成品尺寸；50×50 画布能放入当前钉板并留出边缘。复杂动物、建筑、多层场景优先按 50×50 绘制，简单爱心、星形等可使用较小画布。目前不支持跨板图案。

提高分辨率时要重画轮廓转折、五官、材质分区与明暗。给 16×16 图案补空白到 50×50，或把每格复制几次，都不会增加这些信息。每颗 Mini 的大小保持固定，不按图案尺寸放大模型，也不通过拉近相机弥补图案分辨率。

## 修改与验证

七款图案的绘制源为 `scripts/generate-detailed-patterns.mjs`，包含在 50 格坐标上的轮廓、多层色面和细部笔画。运行 `node scripts/generate-detailed-patterns.mjs` 会确定性重建 `src/Core/Gameplay/Board/DetailedPatternData.ts`；普通构建直接使用已提交的数据，不运行生成器。颜色 ID 在 `src/Rendering/BeadPalette.ts` 注册，使用独立 `detail-*` 色号，不改变老作品的豆色。

`npm test` 检查连通性、实际占用范围、色号、图集上限及旧存档签名。`npm run selfcheck:mini` 在独立组件场景中加载真实 GLB，对所有新增图验证格位命中、原豆/局部熨烫/成品、存档恢复和资源释放；同时输出 `artifacts/mini-check/detailed-gallery.png`。这不是主页面完整键鼠验收。需实际查看输出图，确认五官、轮廓和内部细节仍能在网页材质中辨认。

## 版本与旧进度

新增图使用独立 `atelier-…-50-v1` ID。之前 15 张图案的全部定义（含名称、颜色、格位和缩略图）保持原值，并有整体 SHA-256 回归检查。全部 22 张图案仍通过同一 Application 命令与存档规则访问。

选图页展示八款细致图。原“轻松小图案”的像素爱心、爱心、五角星、小蘑菇、笑脸全部下架，不再出现在选图页，数据仅为兼容已有存档和收藏保留。九款复杂旧图放在“旧版图案”折叠区域；当前作品若为旧图，该区域会自动展开。旧草稿不自动换成新图，制作进度不会被重新解释为另一张图案。
