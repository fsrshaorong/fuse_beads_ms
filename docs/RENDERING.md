# 柔光玩具房渲染

目标来自[指定参考页](https://soft-toy-room-doucechen-0720.eaudoucefish.chatgpt.site/)，对应 2026-09-07 读取的 `ToyRoomScene-CuoAGneb.js`。房间保留原站静态笔触、明影染色和纸感，关闭几何及纹理随时间抖动；密集拼豆与钉板使用本文列出的局部阴影和描边适配。

## 渲染路径

1. Three.js r185 `MeshStandardMaterial.onBeforeCompile`：UV 采样原笔触，在 `map_fragment` 调制底色。
2. 实时阴影 `getShadowMask()` 与阈值、软硬度形成明影遮罩。
3. 原世界坐标三平面贴图公式生成明面、阴影两种颜色，完整替换 outgoingLight。
4. 按原公式完成降低饱和度、最低黑度与底部染色。
5. Three 的 ACES Filmic（曝光 1.08）与 sRGB 输出各执行一次。
6. 在相同深度缓冲上绘制稳定的背面外扩描边，保留前景遮挡关系。

亮色/阴影纹理按原站 sRGB 上传，噪声与三张笔触按数据纹理处理。没有 Bloom、AO、景深、环境图或额外全画面调色。

描边是用户在渲染移植后明确追加的效果，默认开启；原参考包没有这条描边渲染路径。之前的“原始 GLSL 对照零像素差”验证表面着色，不代表添加描边后的整张图仍与原参考相同。

描边配置在 `PainterlyOutline.ts`，对象由材质上的 `userData.painterlyOutline` 显式指定。默认墨色为 `#59424f`，线宽以 CSS 像素计：主体 1.5、深木 1.35、布料 1.15、墙 0.65、未熨烫拼豆 0.25、板子 1。密集拼豆采用细轮廓，避免墨线淹没端面和豆孔；板上以及陈列架上的成品关闭逐豆描边，让熨烫后的色面连贯。地面、窗玻璃、密集定位针、数字提示、透明熨烫纸与窗光不描边；共面无厚度的窗帘和极小刻线、流苏、五官细节也单独排除。合批保留对象覆盖设置。右上美术面板可切换描边或调整粗细，“恢复参考效果”同时恢复描边默认值。

硬边模型使用自有的平滑法线几何副本扩出完整轮廓，原表面法线和材质保持原值；描边 pass 结束或抛错时恢复原几何、材质、回调及 renderer 状态。几何更新、释放和实例矩阵变化会正确反映到下一帧，副本单独管理生命周期。

## 必要适配

- 顶点变形振幅固定为零，笔触采样时刻固定为零。`update(time)` 不能让材质发生时变，也没有可把抖动重新打开的设置。
- 加入实例矩阵支持，使普通模型和 InstancedMesh 拼豆的世界坐标与阴影正确。数字等功能提示使用单独的无光照材质。
- 保留原站在三平面取样处使用的视空间法线运算，避免“修正”为另一种画面。
- 拼豆工作室有不同的几何、布局与连续透视相机；参考玩具房用正交相机。台灯移到本工作室实际灯泡位置。对齐的是渲染管线，不将不同房间的整张截图称为逐像素相同。
- 墙、地基、地毯与玻璃只接收阴影，窗框、窗帘和家具投射阴影，与原站一致。原静态窗光平面保留颜色、透明度和尺寸，适配当前左窗位置；人物闲置摆头也已关闭。

- 仅 `bead` 与 `board` 材质适配微型几何：阴影强度分别乘 0.30、0.25，方向光阴影采样的法线偏移钳制到最多 0.0004 世界单位。默认全局阴影强度 0.92 下，局部有效强度分别为 0.276 与 0.23。房间材质仍采用原强度和 0.026 法线偏移，灯光、阴影图以及参考明影着色公式不变。

这组局部参数用于避免房间尺度的法线偏移在微小豆子旁形成明显错位阴影，并降低密集孔壁和相邻豆投影对图案色面的干扰。它们不是新的全局调色，也没有关闭拼豆、钉板或成品的阴影。表面材质适配与成品逐豆描边关闭是两个独立步骤。

全部图案统一为 2.6 mm Mini 时，沿用上述静态 Shader、材质参数和美术方向；变化只涉及运行时模型、统一钉阵及其摆放尺寸。

## 四人工作室

联机场景的地面由约 8.9×7.3 扩为 11.8×9.4 世界单位，面积约增加至 1.7 倍，桌面、豆板和家具模型保持原尺寸。增加另外三个座位、入口长凳、地垫与墙画；活动边界、桌面碰撞、出生点和座位共用 `Core/Multiplayer/WorkshopLayout.ts`。

房间具备完整四墙、门洞与屋顶。世界镜头绕房间移动时，朝向镜头的墙隐藏，使用方向阈值滞回避免边界反复切换；高位镜头隐藏屋顶，拼豆近景隐藏全部遮挡墙顶。窗、窗台小盆栽、画框及架上作品随所属墙体隐藏，独立柜体和落地家具保留。墙体和装饰边条不投影，避免剖视切换改变室内光照；原窗框、窗帘和家具投影保持原规则。

每人桌面镜头从自己的座位进入，拼豆近景统一图案阅读方向，缩放和平移独立控制。伙伴复用人物网格，围裙和帽子按房间色标区分，世界视角显示姓名，近景显示伙伴光标。渲染 Shader、灯光参数和稳定描边管线保持原值。

`npm run selfcheck:multiplayer-browser` 在真实主页面验证双人位置、独立镜头、共同制作与动态墙体剖视，输出总览、两端棋盘、共同成品及反向镜头截图；这些检查与下面的原始 Shader 像素对照分开报告。

## 验收

`npm run selfcheck:rendering` 独立启动临时 Vite 和隔离 Chrome，获取原站截图与原始 GLSL，在固定几何、相机下做像素对照，检查跨时间稳定性、普通与实例网格、WebGL 错误。首次运行需联网，缓存后可追加 `-- --offline`。证据输出到 `artifacts/rendering/`。

`npm run selfcheck` 验证完整世界→桌面→拼豆→熨烫→恢复→收藏，并输出各阶段截图。美术验收同时查看总览与近景。

`npm run selfcheck:outline` 独立检查描边是否可见、实例几何与动态更新、遮挡、跨时间稳定性和资源释放。表面着色对照仍由 `selfcheck:rendering` 单独验证，不把新增描边混入原 Shader 的像素对照。

`npm run selfcheck:beads` 检查旧 29 格图案在统一 Mini 规格下的主应用制作回归。`npm run selfcheck:mini` 使用独立组件场景检查不同格数图案共用的 Mini GLB、着色和格位命中；它不加载主应用 `main` 或 HUD，不能替代完整界面与键鼠流程验收。美术复查应同时查看未熨烫全板、近景、部分熨烫、成品与世界陈列。

原参考对照验证房间材质公式；`bead`、`board` 的预期画面包含上面的局部适配，不能再将它们描述为未经修改的原站材料。时间稳定性、普通网格与实例网格一致性、孔洞、阴影以及 WebGL 错误应分别检查。性能和像素对照结果以当前脚本输出报告为准，不能把旧几何或旧参数的结果套用到新模型。

## 实体拼豆模型与尺度

网页只加载 `public/models/mini-bead-kit.glb`，其中包含 Mini 未熨烫和成品网格；全部 22 张图案、散豆和收藏共用这一资产。未熨烫外径 2.61 mm、高 2.8 mm 来自 Perler 官方产品资料。所有图案使用同一 145 mm、52×52 钉阵，估计节距为 2.7 mm；板宽在场景内保持 0.87 世界单位，占桌宽约 23%。孔径、倒角、钉距和熨烫后的外形属于建模估值，来源、生成命令和规格报告见 [拼豆模型说明](BEAD_MODELS.md)。旧 `bead-kit.glb` 与 Midi 源文件保留为建模档案，不由网页运行时加载。

模型 `COLOR_0` 为线性中性形体明暗，增强平端面、直侧壁和孔内壁的区别；运行时与实例豆色结合后，继续经过本文着色公式与局部阴影倍率。它不替代实时阴影，也不是方向光或物理 AO 烘焙。相机围绕固定物理板范围构图；换图只改变格位内容，不改变豆子、节距或钉板规格。

默认 50×50「莓果小物」用 1159 颗豆表现有效 40×44 的轮廓、双色叶脉、弧形高光和奶油籽。旧 29×29 草莓有效轮廓为 21×24；只靠近镜头或最近邻复制旧格位，无法增加这些图案信息。统一 Mini 后旧图保持原格数、颜色、cells 和存档签名，不作最近邻放大，因此它在板上和陈列架上的实际面积比旧 Midi 展示更小。

局部熨烫按格位覆盖选择较矮、缩孔、上部圆角方形的成品模型；成品下部保留容钉腔，纸面与熨斗底板按 Mini 高度放置。收藏保留每件作品的已保存格位，并统一使用 Mini 成品与 2.7 mm 节距，不按作品分别缩放。这是静态几何之间的视觉状态切换，不是热力或熔体流动仿真。
